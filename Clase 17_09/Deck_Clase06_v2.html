Lo esencial

Los 3 conceptos que no pueden quedar ambiguos

  1. LazyColumn solo compone lo visible.
    No dibuja las 1000 filas: dibuja las que caben en pantalla y recicla al hacer scroll. Por eso es eficiente.
  2. key le dice a Compose qué fila es cuál.
    Sin key, al reordenar o eliminar elementos Compose puede reutilizar el estado equivocado.
  3. Navegar = cambiar de ruta, no crear pantallas a mano.
    El NavHost es el único que decide qué se muestra según la ruta actual.

Si al final de la clase puedes explicar estos tres con tus propias palabras, la clase cumplió su objetivo.

El problema: 1000 filas

// MAL: compone las 1000 filas de una sola vez
Column(Modifier.verticalScroll(rememberScrollState())) {
    elementos.forEach { elemento ->
        FilaElemento(elemento)
    }
}
  • Column compone todos los hijos, aunque no se vean
  • Con 1000 elementos, la app se congela al abrir la pantalla
  • El consumo de memoria crece linealmente con la lista

La solución no es optimizar la fila: es no componer las filas que no se ven.

LazyColumn

LazyColumn(
    modifier = Modifier.fillMaxSize(),
    contentPadding = PaddingValues(16.dp),
    verticalArrangement = Arrangement.spacedBy(8.dp)
) {
    items(
        items = elementos,
        key = { elemento -> elemento.id }
    ) { elemento ->
        FilaElemento(elemento)
    }
}

items recibe la lista y una lambda que describe una fila. Compose decide cuántas componer.

Bloque 1 · LazyColumn

Cómo funciona el reciclaje

Pantalla visible (5 filas):
[ Fila 1 ]  <- compuesta
[ Fila 2 ]  <- compuesta
[ Fila 3 ]  <- compuesta
[ Fila 4 ]  <- compuesta
[ Fila 5 ]  <- compuesta
   ...      <- NO compuestas (1000 en total)

Al hacer scroll hacia abajo:
[ Fila 1 ]  <- se DESECHA y se reutiliza su espacio
[ Fila 6 ]  <- se COMPONE en el espacio liberado
  • Compose mantiene un número acotado de filas compuestas
  • Al salir de pantalla, la fila se descarta y su espacio se reutiliza
  • El costo de memoria es constante, no proporcional al tamaño de la lista

Bloque 1 · LazyColumn

El bug sin key

// SIN key: el estado de las filas se corrompe
LazyColumn {
    items(elementos) { elemento ->
        var expandido by remember { mutableStateOf(false) }
        FilaExpandible(elemento, expandido) { expandido = !expandido }
    }
}

Síntoma: expandes la fila 3, eliminas la fila 1, y ahora la fila 2 aparece expandida.

Causa: sin key, Compose identifica las filas por posición. Al eliminar un elemento, todas las posiciones se corren y el estado de la fila 3 queda asociado a la fila 2.

// CON key: el estado sigue al elemento correcto
items(elementos, key = { it.id }) { elemento -> /* ... */ }

Bloque 3 · Navigation

Definir rutas

object Rutas {
    const val HOME    = "home"
    const val LISTA   = "lista"
    const val DETALLE = "detalle/{id}"

    fun detalle(id: Int) = "detalle/$id"
}

Las rutas son strings. Los argumentos se declaran con {nombre} y se sustituyen al navegar.

Centralizar las rutas en un object evita errores de tipeo: si escribes "detalle" en un lugar y "detalles" en otro, la navegación falla silenciosamente.

Bloque 3 · Navigation

El NavHost

val navController = rememberNavController()

NavHost(navController = navController, startDestination = Rutas.HOME) {

    composable(Rutas.HOME) {
        PantallaHome(onIrALista = { navController.navigate(Rutas.LISTA) })
    }

    composable(Rutas.LISTA) {
        PantallaLista(onIrADetalle = { id ->
            navController.navigate(Rutas.detalle(id))
        })
    }

    composable(
        route = Rutas.DETALLE,
        arguments = listOf(navArgument("id") { type = NavType.IntType })
    ) { backStackEntry ->
        val id = backStackEntry.arguments?.getInt("id") ?: 0
        PantallaDetalle(id = id)
    }
}

Navegar y volver

// Avanzar
navController.navigate(Rutas.detalle(id))

// Volver a la pantalla anterior
navController.popBackStack()

// Volver hasta una ruta concreta
navController.popBackStack(Rutas.HOME, inclusive = false)

El botón Atrás del sistema funciona automáticamente con el NavHost: no tienes que programarlo.

Ojo: si navegas repetidamente a la misma ruta sin control, la pila crece. Usa launchSingleTop = true para evitarlo.

El flujo completo

HOME
  |  navigate("lista")
  v
LISTA  (LazyColumn con key)
  |  navigate("detalle/$id")
  v
DETALLE  (lee el argumento id)
  |  popBackStack() o botón Atrás
  v
LISTA  (el estado se conserva)

El NavController mantiene una pila de navegación: cada navigate apila, cada popBackStack desapila.

Diagnóstico

El bug de la ruta sin argumento

// Se navega CON argumento...
navController.navigate("detalle/42")

// ...pero se registra SIN declararlo
composable("detalle/{id}") { backStackEntry ->
    val id = backStackEntry.arguments?.getInt("id") ?: 0   // siempre 0
    PantallaDetalle(id = id)
}

Síntoma: la pantalla de detalle siempre muestra el id 0, sin importar qué elemento tocaste.

Causa: falta declarar el argumento en arguments = listOf(navArgument("id") { ... }). Sin esa declaración, el Bundle no contiene la clave.

Los 3 errores más comunes

SíntomaCausa
Crash al navegar a detalleEl argumento {id} no está declarado en arguments
La pantalla no cambiaSe llamó a navigate con una ruta que no existe en el NavHost
El estado de la lista se corrompe al eliminarFalta el parámetro key en items

Los tres producen síntomas distintos pero comparten una causa: una declaración incompleta entre lo que se navega y lo que se registró.
