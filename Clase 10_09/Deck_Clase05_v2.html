Lo esencial

Los 3 conceptos que no pueden quedar ambiguos

  1. Composable = función que describe UI.
    No "crea" un objeto de interfaz: describe cómo debería verse para un estado dado, y puede volver a ejecutarse.
  2. Estado = dato que, al cambiar, hace que la UI se vuelva a dibujar.
    remember lo conserva entre recomposiciones; rememberSaveable lo conserva incluso si la Activity se destruye (rotación).
  3. Modifier = cadena ordenada de configuraciones.
    El orden cambia el resultado.

Si al final de la clase puedes explicar estos tres con tus propias palabras, la clase cumplió su objetivo.

El problema: la UI a mano

// Forma "clásica" (imperativa) — Clase 04
val tvNombre = findViewById<TextView>(R.id.tvNombre)
val btnSumar = findViewById<Button>(R.id.btnSumar)
var contador = 0

btnSumar.setOnClickListener {
    contador++
    tvNombre.text = "Publicaciones: $contador"   // hay que ACORDARSE
}

¿Qué pasa si olvidas la línea tvNombre.text = ...? El dato cambia, pero la pantalla no.

El programador es responsable de mantener sincronizados el dato y la pantalla. Ese es el problema central del enfoque imperativo.

La idea de Compose

// Forma declarativa — Compose
var contador by remember { mutableStateOf(0) }

Text(text = "Publicaciones: $contador")
Button(onClick = { contador++ }) { Text("+") }

Aquí no le dices a la pantalla qué hacer. Describes cómo se ve la pantalla para un valor de contador.

Cuando contador cambia, Compose vuelve a ejecutar la descripción. Nunca tocas la vista.

@Composable: las 3 reglas de oro

@Composable le dice al compilador: "esta función no devuelve nada, pero describe UI".

  1. Un Composable no devuelve un valor (devuelve Unit).
  2. Solo puedes llamar a un Composable desde otro Composable.
  3. Por convención se nombran en PascalCase (SaludoScreen), como si fueran tipos.

Por eso el compilador la trata distinto: le permite llamar a otras funciones @Composable y le inyecta el motor de recomposición.

Spacer y alineación

Spacer es un Composable vacío cuyo único propósito es ocupar espacio:

Spacer(modifier = Modifier.height(16.dp))   // espacio vertical

  • En Column: horizontalAlignment + verticalArrangement
  • En Row es al revés: verticalAlignment + horizontalArrangement

¿Por qué importa Box? Es la única forma de poner un texto encima de un círculo. Lo usarás para el avatar del taller.

Modifier: el orden importa

Versión A — padding antes de background:

Modifier
    .fillMaxWidth()
    .padding(16.dp)                  // primero el padding
    .background(Color(0xFFF3F2EE))   // luego el fondo

El fondo no cubre los 16 dp de padding: queda un margen sin color alrededor.

Versión B — background antes de padding:

Modifier
    .fillMaxWidth()
    .background(Color(0xFFF3F2EE))   // primero el fondo
    .padding(16.dp)                  // luego el padding

El fondo sí cubre todo el ancho, y el texto queda con aire adentro.

Un Modifier se aplica de arriba hacia abajo, como capas de cebolla: el primero envuelve a los siguientes.

El problema: las variables normales no avisan

@Composable
fun ContadorRoto() {
    var contador = 0          // variable normal: Compose NO la observa

    Column(horizontalAlignment = Alignment.CenterHorizontally) {
        Text(text = "Contador: $contador")
        Button(onClick = { contador++ }) { Text("+") }
    }
}

¿Por qué al presionar + no cambia nada en pantalla?

  1. contador es una variable local de Kotlin. Compose no tiene forma de saber que cambió.
  2. Aunque lo supiera, la función ya terminó de ejecutarse: nadie la vuelve a llamar.

La solución: remember + mutableStateOf

@Composable
fun ContadorScreen() {
    var contador by remember { mutableStateOf(0) }

    Column(
        modifier = Modifier.fillMaxSize(),
        horizontalAlignment = Alignment.CenterHorizontally,
        verticalArrangement = Arrangement.Center
    ) {
        Text(text = "Contador: $contador",
             style = MaterialTheme.typography.headlineMedium)

        Spacer(modifier = Modifier.height(16.dp))

        Row {
            Button(onClick = { contador-- }) { Text("-") }
            Spacer(modifier = Modifier.width(16.dp))
            Button(onClick = { contador++ }) { Text("+") }
        }
    }
}

Bloque 3 · Estado

Descompón la línea clave

var contador  by  remember { mutableStateOf(0) }
     |         |      |            |
     |         |      |            +-- valor inicial + contenedor observable
     |         |      +-- "recuerda este valor entre recomposiciones"
     |         +-- delegado: permite contador++ en vez de contador.value++
     +-- variable local que lee el valor actual
  • mutableStateOf(0) → crea un contenedor observable. Compose se suscribe a él.
  • remember { } → guarda ese contenedor en la memoria del Composable. Sin remember, cada recomposición crearía uno nuevo y volvería a 0.
  • by → azúcar sintáctico. Sin by escribirías contador.value++.
// La misma cosa sin `by`
val contador = remember { mutableStateOf(0) }
Text(text = "Contador: ${contador.value}")
Button(onClick = { contador.value++ }) { Text("+") }

Error común: mezclar las dos formas. Si usas by, necesitas import androidx.compose.runtime.getValue y setValue.

Bloque 3 · Recomposición

¿Qué es una recomposición?

1. Compose ejecuta ContadorScreen()  → lee contador (0) → dibuja "Contador: 0"
2. El usuario presiona "+"
3. onClick ejecuta contador++  → mutableStateOf notifica el cambio
4. Compose sabe QUÉ Composables leyeron ese estado → los marca como sucios
5. Compose vuelve a ejecutar SOLO esos Composables → dibuja "Contador: 1"
  • Compose observa qué estado lee cada Composable
  • Cuando ese estado cambia, solo se vuelve a ejecutar (recompone) lo necesario
  • No se redibuja toda la pantalla: es eficiente por diseño, no por optimización manual

MaterialTheme: el sistema de diseño

MaterialTheme es un proveedor de valores de diseño. Todo lo que está dentro de él puede leer:

MaterialTheme.colorScheme.primary          // color principal de la marca
MaterialTheme.colorScheme.onPrimary        // color de texto SOBRE primary
MaterialTheme.colorScheme.surfaceVariant   // fondo suave
MaterialTheme.colorScheme.onSurfaceVariant // texto sobre ese fondo
MaterialTheme.typography.headlineSmall     // escala tipográfica

La convención onX significa "color de contenido que va ENCIMA de X". Usar onPrimary sobre primary garantiza contraste correcto en modo claro y oscuro automáticamente.

remember vs rememberSaveable

El experimento: con remember, llega a 5, rota el emulador. El contador vuelve a 0.

rememberrememberSaveable
Sobrevive a recomposiciónSíSí
Sobrevive a rotaciónNoSí
Sobrevive a muerte del procesoNoSí (vía Bundle)
MecanismoMemoria de la composiciónBundle de estado de la Activity
var contador by rememberSaveable { mutableStateOf(0) }

Rotar destruye y recrea la Activity (Clase 04). remember no sobrevive a eso; rememberSaveable sí.

Regla práctica: si al usuario le molestaría perderlo, usa rememberSaveable.

Bloque 5 · Bug clásico

La lista que no se actualiza

// NO funciona: Compose no observa un ArrayList normal
val logros = remember { mutableListOf("Primer commit") }
logros.add("Nuevo logro")   // la pantalla no cambia

// SÍ funciona: lista observable
val logros = remember { mutableStateListOf("Primer commit") }
logros.add("Nuevo logro")   // dispara recomposición

mutableListOf devuelve un ArrayList común. Compose no lo observa: la referencia es la misma, así que "nada cambió".

remember evita que la lista se recree, pero no la vuelve observable. Ese es el bug de la Parte 2 del taller.

Alternativa: var logros by remember { mutableStateOf(listOf(...)) } y reasignar con logros = logros + x.

Extensión A

Estado elevado (state hoisting)

Un componente reutilizable no debería tener su propio estado. Debe recibir el valor y devolver eventos.

@Composable
fun ContadorPublicaciones(
    valor: Int,
    onIncrementar: () -> Unit,
    onDecrementar: () -> Unit,
    modifier: Modifier = Modifier
) {
    Row(modifier = modifier, verticalAlignment = Alignment.CenterVertically) {
        Button(onClick = onDecrementar, enabled = valor > 0) { Text("-") }
        Text(text = "$valor", style = MaterialTheme.typography.displaySmall)
        Button(onClick = onIncrementar) { Text("+") }
    }
}

El estado sube al padre: var publicaciones by rememberSaveable { mutableStateOf(0) }.

La frase que debes recordar: "El estado baja, los eventos suben." Es la base de MVVM (Clase 08).

Resumen: la fórmula de tres partes

Composable = función + estado + Modifier.

La función describe, el estado dispara, el Modifier configura.

ConceptoEn una frase
@ComposableFunción que describe UI; se puede volver a ejecutar
rememberGuarda un valor mientras el Composable permanece en pantalla
rememberSaveableIgual, pero sobrevive a la rotación
mutableStateOfContenedor que notifica a Compose cuando cambia
mutableStateListOfLista observable: sus cambios sí disparan recomposición
RecomposiciónVolver a ejecutar los Composables cuyo estado leído cambió
